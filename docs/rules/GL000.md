# GL000 no-enforcement-baseline

Default severity: **warn**.

## What it catches

The tool could not work out which migrations to enforce. There is no `--since` flag, no `since` in
the config, and no opt-in migration in the history (a migration that revokes the default table
privileges from `anon`, `authenticated` and `service_role`). Without that boundary, the rules that
check new relations (GL001 to GL006 and GL008) check no file at all. GL007 still runs.

GL000 reports once per run, on the first line of the last migration file. With no migrations it
reports nothing.

## Why it matters

Every Supabase project used to grant new tables in `public` to `anon`, `authenticated` and
`service_role` automatically. Supabase has announced that from 2026-10-30 it stops doing that for
every existing project. Your older migrations were written while the automatic grants existed, so
checking them against the new behaviour would flag almost every table. The tool only enforces the
migrations written after your project stopped getting automatic grants, and it needs to know where
that point is.

A project can be opted in without any migration saying so: from the dashboard, or by the platform
change on 2026-10-30. That is why GL000 does not claim your project is not opted in.

## Failing example

```sql
-- supabase/migrations/20260901000000_create_todos.sql
create table public.todos (
  id bigint generated always as identity primary key,
  title text not null
);
```

Output of `supabase-grants-lint check`:

```text
supabase/migrations/20260901000000_create_todos.sql
  1:1  warn   GL000  No opt-in migration found, so the rules that check new relations (GL001 to GL006, GL008) checked no file. If your project was opted in from the dashboard, or you are past 2026-10-30, set since to the last migration applied before that (supabase-grants-lint init --since next). Otherwise add the opt-in migration that supabase-grants-lint doctor prints.
              docs  https://github.com/guptaaman678/supabase-grants-lint/blob/v0.1.0/docs/rules/GL000.md

0 errors, 1 warning  (1 file, 1 relation, 0.0s)
```

## Fix

Pick the one that matches your project.

Your project still gets automatic grants: add the opt-in migration that
`supabase-grants-lint doctor` prints. Everything after it is enforced.

```sql
-- supabase/migrations/20261001000000_revoke_automatic_grants.sql
alter default privileges for role postgres in schema public
  revoke all on tables from anon, authenticated, service_role;
alter default privileges for role postgres in schema public
  revoke all on sequences from anon, authenticated, service_role;
```

Your project was opted in from the dashboard, or it is past 2026-10-30: set `since` to the last
migration applied before that, in `grants-lint.config.json` (`supabase-grants-lint init --since next`
writes it for you). The tool then assumes the platform revoke just before the next migration (see
[`platformRevokeAtSince`](../configuration.md#platformrevokeatsince)).

```json grants-lint.config.json
{
  "since": "20260901000000"
}
```

## When it is safe to disable

When you only want the replay check (GL007) and have decided not to enforce anything else. Setting
`since` is almost always the better answer, because it turns the other rules on.

## Configuration

- [`since`](../configuration.md#since) and the `--since` flag set the boundary; `"none"` enforces
  every file.
- Turn the rule off with `"rules": { "GL000": "off" }`.
