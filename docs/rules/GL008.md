# GL008 leftover-privileges

Default severity: **warn**.

## What it catches

A relation created in an enforced migration where, at the end of that migration, `anon`,
`authenticated` or a role in [`clientRoles`](../configuration.md#clientroles) still holds
`truncate`, `references` or `trigger` (and `maintain`, when
[`postgresMajor`](../configuration.md#postgresmajor) is 17 or later), directly or through `PUBLIC`.

## Why it matters

The revoke Supabase published for the change removes `select`, `insert`, `update` and `delete` on
tables, and `usage` and `select` on sequences. The old default was `grant all`, so it leaves
`truncate`, `references` and `trigger` (plus `maintain` on Postgres 17) behind on every table
created while the default was still in place, and on tables created by a `grant all`. The Data API
never needs them. `truncate` and `references` are not subject to row level security, so they are
access your policies do not control.

## Failing example

The opt-in below copies the revoke Supabase published, which is narrower than `revoke all`.

```sql
-- supabase/migrations/20261001000000_revoke_automatic_grants.sql
alter default privileges for role postgres in schema public
  revoke select, insert, update, delete on tables from anon, authenticated, service_role;
alter default privileges for role postgres in schema public
  revoke usage, select on sequences from anon, authenticated, service_role;
```

```sql
-- supabase/migrations/20261002120000_add_todos.sql
create table public.todos (
  id bigint generated always as identity primary key,
  user_id uuid not null default auth.uid(),
  title text not null
);
alter table public.todos enable row level security;
grant select, insert, update, delete on public.todos to authenticated, service_role;
create policy "Users manage their todos" on public.todos
  for all to authenticated using (auth.uid() = user_id);
```

Output of `supabase-grants-lint check`:

```text
supabase/migrations/20261002120000_add_todos.sql
  2:1  warn   GL008  public.todos still grants truncate, references, trigger to anon, authenticated, left over from the default privileges or a grant all: the Data API never needs them, and TRUNCATE and REFERENCES are not subject to row level security. Revoke them in the same migration.
              fix   revoke truncate, references, trigger on public.todos from anon, authenticated;
              docs  https://github.com/guptaaman678/supabase-grants-lint/blob/v0.1.0/docs/rules/GL008.md

0 errors, 1 warning  (2 files, 1 relation, 0.0s)
```

## Fix

Revoke them in the same migration. The fix line leaves out `maintain` unless `postgresMajor` is 17
or later, because naming it fails on older servers.

```sql
-- supabase/migrations/20261002120000_add_todos.sql
create table public.todos (
  id bigint generated always as identity primary key,
  user_id uuid not null default auth.uid(),
  title text not null
);
alter table public.todos enable row level security;
grant select, insert, update, delete on public.todos to authenticated, service_role;
revoke truncate, references, trigger on public.todos from anon, authenticated;
create policy "Users manage their todos" on public.todos
  for all to authenticated using (auth.uid() = user_id);
```

To stop new tables getting them at all, opt in with `revoke all on tables` and
`revoke all on sequences`, as `supabase-grants-lint doctor` prints.

## When it is safe to disable

When you accept the leftovers for now and plan to revoke them in one go later. It is a warning
because nothing breaks; it is extra access, not missing access.

## Configuration

- [`postgresMajor`](../configuration.md#postgresmajor) decides whether `maintain` is checked.
- [`clientRoles`](../configuration.md#clientroles) adds roles to check.
- Suppress one finding with `-- grants-lint-disable-next-line GL008: <reason>` on the line above
  the `create` statement, or an [`ignore`](../configuration.md#ignore) entry.
